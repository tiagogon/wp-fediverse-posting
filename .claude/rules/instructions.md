## Portability contract

This plugin is public and must work on any WordPress site: **no ACF, no theme coupling, no site-specific post-type or taxonomy slugs in code.** Site-specific behaviour goes through the filters listed in the README (a theme hooks `fediverse_posting_language`, `fediverse_posting_fallback_image_id`, …). Trait names carry the `Fediverse_` prefix because the sibling Instagram plugin declares unprefixed traits (`Settings_Page_Trait`…) and both run on the same site.

## Architecture

- `wp-fediverse-posting.php` — `Fediverse_Posting`: settings access (`get_settings()` merges `defaults()`; the option is never autoloaded because it holds tokens), the network registry (`networks()`, `network( $id )`, `connected_networks()`; `is_connected()` = **any** network), `default_destinations()`, log, activation. Connections live under `networks[<id>]` in the option (`network_settings()` / `update_network_settings()`); 1.0's flat `instance/access_token/account` keys are moved there once by `maybe_migrate_settings()` (`settings_version`). Traits:
  - `includes/trait-settings-page.php` — menu (Planner + Settings), Settings API, `sanitize_settings()` (hidden `_source_page` = `planner` | `settings`; each page only writes its own keys), notices (each network contributes `connection_notice_messages()`), `enqueue_admin_assets()` + `fediverseConfig` (`networks{ id: { label, maxChars, maxMedia, hardLimit, account } }`).
  - `includes/trait-content.php` — placeholders, CamelCase hashtags (`hashtagify()`: multi-word only, numbers-only terms skipped), `excerpt_for()`, image choice (`resolve_media_ids( $row, $post, $limits )`), `alt_text_for( …, $max )`, `prepare_media_file( $id, $limits )` (original if the network accepts its type and size, else the largest generated size, else a download, else `shrink_image_file()` re-encodes a JPEG). Network-neutral: it never counts characters.
- `includes/networks/` — one class per destination, all implementing `Fediverse_Network` (`class-network.php`: `id()`, `label()`, `is_connected()` **from stored state only, never HTTP**, `account()`, `limits()` { max_characters, max_media, image_size_limit, image_types, alt_max, url_length, hard_limit }, `count_characters()`, `truncate()`, `template_for_row()`, `supports()`, `publish( $row, $post, $text, $files, $context )` → { id, url, network }, `delete()`, `disconnect()`).
  - `class-network-mastodon.php` — `Fediverse_Network_Mastodon` `use`s the two traits: `includes/trait-oauth.php` (Connect via `POST /api/v1/apps`, once per server + redirect URI in option `fediverse_posting_apps`, `/oauth/authorize` with a one-time `state` transient, callback at `admin-post.php?action=fediverse_oauth_callback`, token fallback, Disconnect via `/oauth/revoke`; tokens don't expire) and `includes/trait-mastodon-api.php` (statuses as JSON so `media_ids` is a real array; errors are `WP_Error` with data `status`, `retryable`, `retry_at`; `instance_limits()` caches `/api/v2/instance` for a day; `upload_media()` polls while the server answers 202). URL counting (`url_length`) lives here. Filter `fediverse_posting_status_params`.
  - `class-network-bluesky.php` — `Fediverse_Network_Bluesky`: `xrpc_raw()` (static, any PDS) / `xrpc()` (signed, refreshes first, retries once on ExpiredToken), `upload_blob()`, `publish()` (facets, `embed.images` for galleries and standalone rows, `embed.external` card for link rows, `langs`, self-labels; never both embeds), `delete()`, `profile()`, duplicate check through `listRecords` when `$context['attempts'] > 0`. Filter `fediverse_posting_bluesky_record`. Limits are static (300 graphemes, 3000 bytes, 4 images of 1 MB, alt 2000, `hard_limit` false).
  - `class-bluesky-session.php` — `Fediverse_Bluesky_Session` interface + `Fediverse_Bluesky_App_Password_Session` (createSession / refreshSession / re-login with the stored app password). Session state (did, pds_url, jwts, account) is in its **own option** `fediverse_posting_bluesky_session`, never in the settings option (the Settings form rewrites that one wholesale). `method` in the settings picks the implementation: OAuth plugs in here later.
  - `class-bluesky-text.php` — `graphemes()`, `facets()` (**byte** offsets: preg offsets, never `mb_strpos`), `truncate_words()` (word boundary, "…", keeps the last URL, 3000-byte cap).
- `fediverse-queue.php` — `Fediverse_Queue`: tables `{prefix}fediverse_queue` and `{prefix}fediverse_queue_targets` (`DB_VERSION`, upgraded on `plugins_loaded` per site; `migrate_targets()` gives 1.0 rows a `mastodon` target), weekly slots (ported from instagram-posting-api), `send_row()` → `send_target()` per due target → `settle_row()`, retries per target, post lifecycle, cron. Traits: `includes/trait-queue-ajax.php` (every AJAX action; `destinations[]`, `network_templates[id]`, `target` for retry / delete_remote), `includes/trait-queue-editor.php` (meta box).
- `fediverse-queue-settings.php` — every piece of HTML: one connection card per network, chips, schedule, rows (per-target lines, per-target View / Delete / Retry), list, box, composer (destinations, Bluesky text, label picker, one preview per network).
- `assets/js/fediverse-admin.js` — one `Box` per `.fedi-box`; the composer switches `data-mode` between `post` and `standalone`; `destinations()` drives `.fedi-only-mastodon` / `.fedi-only-bluesky` / `.fedi-network-text` / the previews.
- `assets/css/fediverse-admin.css` — colour tokens only (`--fedi-*`, with dark overrides for "Dark Mode for WP Dashboard"); never a colour literal elsewhere.

## Rules that are easy to break

- **Reserved words**: `trigger` and `sensitive` are MySQL keywords — columns are `trigger_type` and `is_sensitive`.
- **Never send twice**: a row is claimed with `UPDATE … SET status='processing' WHERE id=%d AND status='scheduled'` and only the caller that changed 1 row sends. Each target is updated **right after its own publish**, so a stuck row (`processing` > 15 min) can go back to `scheduled` and only still-pending targets are sent again. Mastodon's Idempotency-Key is `wpfp-<site hash>-<row id>` with **no** attempt number. Bluesky has none: the stuck reset bumps pending targets to `attempts ≥ 1`, which makes `publish()` look for an identical post of the last hour first.
- **One row, N targets**: the row owns time (slot, trigger, pause); a target owns its outcome (`pending | published | failed | removed`, `attempts`, `retry_at`, `remote_id`, `remote_url`). `settle_row()` derives the row: retrying → `scheduled` at the earliest `retry_at`; a pending target on a disconnected network → `scheduled` (time unchanged); any failed → `failed` (one email per pass); all published/removed → `published`/`removed`. Row `attempts` = max target attempts.
- **Not connected ≠ failed**, per target: `process_queue()` only picks rows with a due pending target on a connected network (JOIN), and `send_row()` skips targets whose network is not connected.
- **Length is never fatal on Bluesky** (`hard_limit` false): the preview warns and shows the shortened text; `send_target()` calls `$network->truncate()`. Mastodon keeps failing hard over its limit.
- **Editing a row** (`sync_targets()`): ticked networks without a target get a pending one, failed targets ticked again go back to pending, pending targets unticked disappear; published/removed targets are never touched (the composer shows them locked).
- **Templates are rendered at send time** (and for the preview), never stored rendered.
- **Hashtags**: `render_template()` keeps one lowercase `$seen` list per call, seeded with hashtags typed literally in the template; `hashtags_for()` runs, in order: `only=`/`not=` (term name or slug, lowercase) → `:deepest`/`:top` → `hashtag_exclude` (term name or CamelCase tag, case-insensitive) → the `fediverse_posting_hashtag` filter → the seen list → `:max=N`. Unrecognised modifier parts go to `$mods['unknown']` and the placeholder is reported in `$unknown` (preview warning) while still rendering. Modifiers are parsed by `parse_modifiers()`; `:deepest`/`:top` only act on hierarchical taxonomies.
- **Starting text**: always `default_template_for( $post_type )` (own text from `post_type_templates`, else `default_template`). A network's own text comes from `network_template_for( $network_id, $post_type )` (`network_templates[<network>][<post_type>]`). Queue rows store their own copy of both (`template`, `network_templates` JSON), so changing Settings never rewrites queued rows. `Fediverse_Network::template_for_row()` picks the row's own text for that network, else the common one.
- **Text is stored as typed**: `clean_text()` (unslash, UTF-8 check, newline normalisation). Never `sanitize_textarea_field()` — it turns `<` into `&lt;`. Escape on output.
- **Rows are rendered only in PHP** (`fediverse_render_list()`), returned as `html` by every AJAX action. A row shows the full rendered text (`fediverse_linkify_text()`, same shortening rule as `linkify()` in the JS; clamped to 4 lines, `<details>` "Show all" for long ones), thumbnails of `resolve_media_ids()` with a "no alt" flag, and in the Planner a view link (permalink, or `get_preview_post_link()` when not public) plus "Edit post".
- **Meta box**: block-editor compatible, everything over AJAX. Radios need a `name` to group; they get unique names the plugin never reads.
- **Queue order** is `position`; only `trigger_type = 'queue'` rows with `attempts = 0` are re-slotted by `recalculate_schedule()`. Rows in a retry back-off keep their time; fixed-time rows (`at`) block their moment.
- `get_post( 0 )` returns the global post: always `$id ? get_post( $id ) : null`.

## Deployment

`main` is a release branch: every push to `main` is deployed automatically to the maintainer's production site by a signed GitHub webhook, so never push unfinished work to `main`. Production runs on a case-sensitive Linux filesystem while local dev is macOS; use `git mv` with a temp name for case-only renames.

Server-side details live in the git-ignored `CLAUDE.local.md` at the plugin root. Never copy them into tracked files — this repo is public.

## Decision-making protocol

Never assume functional or UX requirements — ask the maintainer before implementing anything that changes what users see or what gets posted. Code structure, naming and performance can be decided autonomously.
